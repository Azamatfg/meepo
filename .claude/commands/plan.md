# Plan — структурированное планирование перед реализацией

Перед тем как писать код, создай план.

## Шаг 1: Понимание задачи
- Что просит пользователь?
- Какой конечный результат?
- Есть ли Figma дизайн? (если да — загрузи через MCP)

## Шаг 2: Исследование
- Прочитай существующий код в затрагиваемых файлах
- Найди существующие паттерны (как сделано похожее)
- Проверь БД схему если нужны новые таблицы
- Проверь API если нужны новые эндпоинты

## Шаг 3: Архитектура
- Какие файлы создать/изменить?
- Нужны ли новые модели/таблицы/миграции?
- Нужны ли новые API эндпоинты?
- Можно ли переиспользовать существующий код?

## Шаг 4: Разбивка на фазы
- Разбей на 3-5 фаз
- Каждая фаза должна быть самодостаточной (можно деплоить)
- Укажи зависимости между фазами

## Шаг 5: Оценка
- Таблица: фаза → файлы → сложность (Low/Medium/High)
- Общая оценка в днях

## Формат вывода
Кратко, структурировано, без воды. Покажи пользователю план и жди подтверждения перед реализацией.
