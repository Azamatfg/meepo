# Ship — релизный flow

Выполни полный цикл подготовки к отправке кода:

## 1. Проверка
- `git status` — определи, какие изменения сделаны В ЭТОЙ сессии; чужие (параллельные сессии) не трогать
- Сборка/type-check по стеку (см. CLAUDE.md)

## 2. Тесты (если есть)

## 3. Коммит
- Стейджить только свои файлы явными путями (никаких `git add -A` / `.`), проверить `git diff --cached --name-only`
- Осмысленный commit message на английском (feat/fix/chore)
- Добавь Co-Authored-By

## 4. Push
- `git pull --rebase` перед push (если дерево грязное чужими файлами — `git pull --no-rebase`)
- Разреши конфликты если есть
- `git push`

## 5. Отчёт
- Кратко что отправлено (файлы, суть изменений)
- Если были проблемы — сообщи

НЕ делай: force push, amend чужих коммитов, push без проверки сборки, stash.
