# Deliver — от проверки до деплоя

Полный цикл. Любой шаг упал — стоп, отчёт, что упало и почему; дальше не идти.

## 1. Проверка
- `git status` — определи, какие изменения сделаны В ЭТОЙ сессии; чужие (параллельные сессии) не трогать
- Сборка/type-check по стеку (см. CLAUDE.md)

## 2. Тесты
- Тесты проекта (команда в CLAUDE.md). Красные — стоп.

## 3. Коммит
- Стейджить только свои файлы явными путями (никаких `git add -A` / `.`), проверить `git diff --cached --name-only`
- Осмысленный commit message на английском (feat/fix/chore)
- Добавь Co-Authored-By

## 4. Push
- `git pull --rebase` перед push (если дерево грязное чужими файлами — `git pull --no-rebase`)
- Разреши конфликты если есть
- `git push`

## 5. CI
- `gh run list --commit $(git rev-parse HEAD) --json databaseId,name,status,conclusion` — прогоны этого коммита
  (появляются через несколько секунд; нет ни одного за минуту — у ветки нет CI на push, так и сказать)
- `gh run watch <id> --exit-status` по каждому. Красный — `gh run view <id> --log-failed`, стоп с причиной.

## 6. Сборка и деплой
- Как описано в разделе «Deploy» CLAUDE.md проекта. Нет такого раздела — спросить, как деплоить, и не угадывать.
- После деплоя — проверить, что он поднялся (health, версия, лог), как там же описано.

## 7. Отчёт
- Что отправлено (коммит сообщением), CI (зелёный / какой упал), что задеплоено и где проверено

НЕ делай: force push, amend чужих коммитов, push без проверки сборки, stash, деплой при красном CI.
