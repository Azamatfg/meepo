# Meepo — дизайн

Дополнение к `SPEC.md`. Всё, что касается внешнего вида, берётся отсюда.

## 1. Концепция

Пиксель-арт RTS конца 90-х. **Игрок — это пользователь**, его на карте нет: он присутствует только через курсор, рамку выделения и Tab.
**Юниты — это сессии.** Все юниты одинаковые, лидера нет, никаких корон.

| В игре | В Meepo |
|---|---|
| Юнит в капюшоне у терминала | Сессия Claude Code |
| Зелёный круг под юнитом | Сессия выбрана / работает |
| Оранжевый круг и «!» над головой | Сессия ждёт тебя |
| Юнит сидит у выключенного терминала | Нет активных сессий |
| Рамка выделения мышкой | Выбор нескольких сессий для общей команды |
| Серое окно с рамкой | Любая панель интерфейса |

## 2. Референсы

Положи картинки в репозиторий и сверяйся с ними при вёрстке:

- `assets/ref/master.png` — рамка выделения над юнитами. **Главный эталон стиля.**
- `assets/ref/waiting.png` — юнит с оранжевым кругом и «!».
- `assets/ref/empty.png` — пустое состояние.
- `assets/ref/icon.png` — иконка приложения.

Картинки — это эталон настроения и цвета, а не макет раскладки. Раскладку окна задаёт раздел 5.

## 3. Токены

Цвета сняты с референсов.

| Токен | Цвет | Где |
|---|---|---|
| `grass` | `#2C4B1E` | основной фон панелей |
| `grassLight` | `#427F41` | ховеры, светлые участки |
| `grassDeep` | `#233624` | фон пустых состояний, тёмные зоны |
| `dirt` | `#3F2F1D` | дорожки, разделители, подложки списков |
| `hood` | `#7B4B2C` | вторичный тёплый акцент |
| `selection` | `#11F10F` | выбранное, активное, «работает» |
| `selectionSoft` | `#44922D` | невыбранные круги, неактивные полоски |
| `alert` | `#F16704` | ждёт пользователя, «!» |
| `screen` | `#1EC8EC` | всё, что про терминал и код |
| `screenDeep` | `#336C81` | корпуса терминалов, вторичный голубой |
| `frameLight` | `#B3B3B2` | светлая грань рамки окна |
| `frameMid` | `#636363` | тело рамки |
| `frameDark` | `#404040` | тёмная грань рамки |
| `terminalBg` | `#0E1710` | фон терминала (не трава: там читают код) |
| `danger` | `#E0402A` | ошибка, упавший CI |
| `warn` | `#F2C230` | пора sync |

Правила:
- `selection` только для выбранного и активного. Если зелёный везде, он перестаёт что-либо значить.
- `alert` только для «ждёт тебя». Это самый важный сигнал в приложении.
- Текст: светлый `#E8F0E0` на тёмных фонах, контраст не ниже 4.5:1.

## 4. Шрифты

Все под открытой лицензией OFL, можно вшивать в приложение.

- **Silkscreen** — заголовки, бейджи, кнопки. Только крупно (от 16 px), мелкий пиксельный шрифт не читается.
- **JetBrains Mono** — терминал, ветки, числа.
- Системный шрифт — мелкий служебный текст, где важнее читаемость.

## 5. Компоненты

### Окно-рамка
Как в референсах: серая рамка в стиле Windows 95.
- Внешняя грань: сверху и слева `frameLight`, снизу и справа `frameDark`, по 2 px.
- Тело рамки `frameMid`, внутренняя грань наоборот (вдавленная).
- Никаких скруглений, никаких мягких теней.

### Карточка юнита (сессия)
- Портрет: спрайт юнита (раздел 6) 48×48, над кругом выделения.
- Круг выделения по состоянию:
  - выбрана — толстый `selection` с лёгким свечением;
  - работает — тонкий `selectionSoft`, медленная пульсация;
  - ждёт тебя — `alert`, пульсация быстрее, «!» над портретом;
  - пора sync — `warn`;
  - ошибка — `danger`;
  - закрыта — без круга.
- Имя проекта, ветка (JetBrains Mono), этап.
- Полоска контекста: пиксельная, из сегментов по 4 px с зазором 1 px, в тёмной вдавленной рамке. Цвет: до 50% `selection`, до 70% `warn`, дальше `alert`.
- Число токенов в маленькой табличке справа от полоски.

### Командные кнопки
Квадратные 36×36, выпуклая рамка как у окна, внутри 16-битная иконка. Нажатие — рамка становится вдавленной. Подпись-хоткей мелко в углу.

### Терминал
Внутри вдавленной рамки, фон `terminalBg`, текст JetBrains Mono. Курсор — мигающий блок `selection`.

### Выделение рамкой
В режиме карты (раздел 5, «Карта») можно протянуть мышкой зелёную рамку по юнитам: выделенные получают толстый зелёный круг, внизу появляется панель общих команд (например, `/sync` для всех выбранных). Это прямо картинка `master.png`, ставшая функцией.

### Пустое состояние
Картинка `empty.png` в рамке окна, под ней одна кнопка: «Запустить сессию».

## 6. Спрайты

Для интерфейса нужны отдельные спрайты юнита на прозрачном фоне. Генерировать с `master.png` как референсом:

```
Same exact art style as the reference image. Sprite sheet on a transparent
background, pixel art, the same hooded goblin at a blue terminal, four
separate frames in a row: 1) typing, 2) typing with the other hand,
3) turned back towards the viewer with an orange exclamation mark above,
4) sitting idle next to a switched-off terminal. Same size and camera
angle for all frames, isometric view, no ground, no shadows, no text.
```

Правила пиксель-арта в коде:
- масштабировать только целыми множителями (2×, 3×);
- интерполяция выключена (`.interpolation(.none)` в SwiftUI);
- никакого размытия и сглаживания картинок.

## 7. Иконки приложения

- **Иконка приложения** — из `icon.png`: обрезать до квадрата, экспортировать все размеры AppIcon. Проверить, что читается в 32×32.
- **Иконка в строке меню** — отдельная, простая: силуэт капюшона 18×18 в один цвет, как template image (macOS сама перекрашивает её под светлую и тёмную тему). Бейдж с числом ждущих — `alert`.

## 8. Движение

Анимаций мало, и все «игровые»:
- пульсация кругов (раздел 5);
- переключение по Tab: круг выделения «перепрыгивает» на следующую карточку за 120 мс;
- появление «!» — короткий подскок на 2 px.
Никаких плавных фейдов и параллакса: это ломает ощущение старой игры.

## 9. Ограничения

- Никаких названий, текстов, интерфейсов и персонажей из существующих игр. Только оригинальная графика.
- В README и описаниях не упоминать конкретные игры. Допустимо: «inspired by classic 90s RTS games».
- Все картинки и спрайты хранить в `assets/`, исходники генераций тоже, чтобы потом можно было перегенерировать в том же стиле.
